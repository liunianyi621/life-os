## 新数据边界

- 当前空间选择键：`lifeos-active-profile-v1`，内容为 `{version:1,key,createdAt}`。
- 新数据主键：`lifeos-profile-v1-<UUID>`。正常用户数据仍使用原有完整状态结构，不另建金币账本。
- 用户确认前不创建新空间；取消不写入。
- 确认后先保存并校验新状态，成功后才记住选择。新状态为 0 金币、空任务/重点/习惯/提醒/复盘/目标及历史；基金使用原有零投入默认模板。
- 创建和切换受独占锁保护。若保存失败，保留原选择，不假装成功；中断留下的新空空间不删除。
- 如果已有选择键损坏，重新选择时先原样保存该选择键的快照，再使用新 UUID；旧空间及所有原始 v1/v2/v3 和历史快照不删除。
- 重复创建或其他窗口同时切换时，不能把已创建的新空间替换成另一份默认空状态。
- 以后启动优先读取选定的新空间，不扫描、迁移、合并或结算旧空间。旧页面写旧键不会触发新空间只读或覆盖新余额。
- 备份、导入前快照、主数据保存使用当前空间主键；显式重置新空间时也不删除原先保留的旧键。
- 不改变金币奖惩、任务/习惯/复盘/目标业务逻辑，不在本次继续开发三模式。

## 编辑权

- 使用浏览器原生 Web Locks，没有需要清理的持久化“锁标记”。页面关闭由浏览器释放锁。
- pagehide / 切后台时先保存有效草稿、释放编辑权；pageshow / 回前台重新检查数据并申请编辑权。
- 同一数据空间仍只有一个编辑者；不同空间隔离，不依赖旧版窗口配合放行。
- 只有收到当前可响应编辑实例的探测回复，才显示“另一窗口正在编辑”。没有回复时显示等待/重试，不冒充已知有其他活跃窗口。
- 编辑权释放后自动重试；主动切换最多等待 4 秒，不留下永久排队或错误只读。不会强行夺走未响应窗口的锁而产生两个写入者。
- 每次写入仍核对数据原始版本及空间选择，旧内存不能静默写回覆盖较新数据。

## 手机上线后验收

1. 联网后重新打开 LifeOS PWA；不要卸载或清理网站数据。
2. 若提示旧数据异常，点“开始全新使用”→“确认开始”。无需连接 Mac、Console 或导出。
3. 新建一项今日重点并完成，确认金币增加 50；关闭并重新打开，确认该状态和金币仍在。
4. 新建一项习惯、保存一条复盘、创建一个长期目标，切换底部四个 Tab；切到后台再回来应能继续编辑。

如果存储本身被浏览器禁止或网站配额已满，必须显示保存失败，不能承诺已成功持久化，更不能通过清除旧数据强行解决。
